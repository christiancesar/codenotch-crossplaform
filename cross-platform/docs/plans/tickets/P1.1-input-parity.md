# Ticket P1.1 — Drag and no-activate parity on Linux

- Phase: **1** (unblocks real desktop use) · Depends on: Epic 0 (done) · Lane: main.rs,
  runs in parallel with P1.2 (disjoint file)
- Verifies on: real X11 (`DISPLAY=:1`, GNOME/Mutter, this host).

## Goal

Two Linux stubs in `codenotch/src/main.rs` currently make the notch behave differently from
Windows/macOS in ways a user would notice immediately:

1. `left_button_down()` always returns `false` on Linux (`#[cfg(not(windows))]`, ≈ main.rs:156).
   `drag_begin`'s poll loop checks this every 8ms to decide whether the mouse button is still
   held; since it is always `false`, the loop exits on its first iteration and **dragging the
   notch along the edge does not work at all** on Linux.
2. `noactivate()` is a no-op on Linux (≈ main.rs:254). On Windows it applies
   `WS_EX_NOACTIVATE`/`WS_EX_TOOLWINDOW` so the notch never steals keyboard focus from whatever
   the user is doing. Without an equivalent, clicking the notch (even through the click-through
   toggle) can raise/focus it and steal focus from the terminal/editor underneath.

## Scope (exactly this)

1. **`left_button_down()` on Linux**: query the X11 pointer button mask via `x11rb`
   (`query_pointer` on the root window, check `mask & ButtonPress` for button 1) instead of a
   Windows API. Keep the function signature identical so `drag_begin` needs no changes.
2. **`noactivate()` on Linux**: prevent the notch window from taking input focus when clicked.
   The GDK/GTK-level lever is `gtk_window.set_accept_focus(false)` (or, if tauri exposes it more
   directly through its own window handle, prefer that with no new dependency) — apply it once
   after the window is realized. `gtk`/`gdk` are already dependencies (used by `x11_struts.rs`'s
   `xid_of`).
3. Log what was applied via `applog`, matching the style already used in `window_layer/x11_struts.rs`.

## Dependencies allowed

None new — `x11rb`, `gtk`, `gdk` are already in `Cargo.toml`'s `[target.'cfg(not(windows))'.dependencies]`.
