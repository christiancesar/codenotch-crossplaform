# Ticket P1.2 — Focus detection on Linux (X11 active-window)

## Goal

`codenotch/src/focus.rs` has two Linux stubs that always return `false`:

- `focus_terminal(_claude_pid: u32) -> bool` (≈118) — on Windows, brings the terminal running a
  given Claude Code process to the foreground when its notch card is clicked.
- `focus_claude_desktop() -> bool` (≈272) — same idea for the Claude desktop app.

Because both are stubs, **clicking a session card on Linux never raises the owning
window** — the notch shows the session but clicking it does nothing visible.

## Scope (exactly this)

1. Implement `focus_claude_desktop()` and `focus_terminal(claude_pid)` for Linux using EWMH:
   - Enumerate windows via `_NET_CLIENT_LIST` on the root window (x11rb).
   - For each, read `_NET_WM_PID` to match against `claude_pid` (terminal case) or against the
     known Claude-desktop process names via the existing `proc_maps()`/`pid_hits_chain()` helpers
     (desktop case) — reuse the process-tree matching already in this file, do not duplicate it.
   - On match, activate the window: send a `_NET_ACTIVE_WINDOW` client message to the root
     window (the standard EWMH way to ask the WM to raise+focus a window; a direct
     `XSetInputFocus` is not enough and can be refused by the WM). Return `true` only if a window
     was actually found and the message was sent.
2. If no window is found (process has no mapped window, or `_NET_CLIENT_LIST`/`_NET_WM_PID`
   are unsupported by the running WM), return `false` — same honesty contract as today, just now
   backed by a real attempt instead of an unconditional stub.
